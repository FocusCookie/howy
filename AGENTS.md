# AGENTS.md

Guidance for AI coding agents (Claude Code, Codex, …) working on **Howy**, a
macOS menu-bar Eisenhower matrix with desktop widgets. `CLAUDE.md` is a symlink
to this file, so edit only `AGENTS.md`.

## Use the Axiom skills

Use the **Axiom** skill suite (`axiom@axiom-marketplace`, turned on in
`.claude/settings.local.json`) for all Apple-platform work. Load the matching
skill before you write code:

| Area                                                    | Skill                                         |
| ------------------------------------------------------- | --------------------------------------------- |
| Menu-bar app, windows, panels, sandbox, AppKit bridging | `axiom-macos`                                 |
| SwiftUI views, layout, animation                        | `axiom-swiftui`                               |
| SwiftData store, schema, migrations                     | `axiom-data`                                  |
| Widgets, App Intents, URL scheme, login item            | `axiom-integration`                           |
| Swift 6 concurrency, `@MainActor`, `Sendable`           | `axiom-concurrency`                           |
| Tests (Swift Testing)                                   | `axiom-testing`                               |
| Build failures, Xcode trouble                           | `axiom-build`                                 |
| Apple API questions                                     | `axiom-apple-docs` (don't answer from memory) |

**One deliberate exception:** Axiom recommends `group.`-prefixed App Groups.
Howy uses the **team-prefixed** form `$(TeamIdentifierPrefix)io.lichtwart.howy`
instead. On recent macOS a free Personal Team can't register `group.` IDs, and
when that fails the widget silently doesn't load. Keep the team-prefixed form.

## Platform

- macOS 27 deployment target, Xcode 27, Swift 6 (strict concurrency), SwiftUI +
  AppKit.
- Signing: automatic, Personal Team `GQ9M79TF33` ("Apple Development"). Not
  "Sign to Run Locally".
- Both the app and the widget extension are **sandboxed**. macOS won't load an
  unsandboxed widget.
- For personal use only: no App Store and no notarisation.

## Project layout

```
project.yml              XcodeGen spec. This is the source of truth for the Xcode project
Howy.xcodeproj/          Generated by XcodeGen. Don't hand-edit; regenerate it
Howy/                    Menu-bar app (target "Howy"): panels, views, AppKit glue
HowyWidgets/             WidgetKit extension: Matrix + Quadrant widgets, CompleteTodo intent
Packages/HowyCore/       Swift package with all logic and state machines, plus its tests
  Sources/HowyCore/      TodoStore (SwiftData), flows, drafts, attachments, Markdown, deep links
  Tests/HowyCoreTests/   Swift Testing suites
README.md                What Howy does and how to use it (features, keys, settings)
CHANGELOG.md             Release history; Unreleased lists what changed since the last release
```

There is no separate spec. The behaviour is described in `README.md`,
`CHANGELOG.md` and the doc comments of the flows in `HowyCore`.

### Architecture rules

- **Logic lives in `HowyCore`, views stay thin.** The quick-entry, browse,
  launcher and archive behaviour are UI-independent state machines
  (`QuickEntryFlow`, `BrowseFlow`, `LauncherFlow`, `ArchiveFlow`) that take key
  events. SwiftUI and AppKit only render state and forward keys. Key-code
  mapping (`KeyMapping`) is in core too.
- **`TodoStore`** is the only way to read or write todos. It uses a versioned
  SwiftData schema (`Schema.swift`, currently v1, with a migration plan) inside
  the App Group container, shared by the app and the widget. Every write that
  changes something reloads the widget timelines. Time comes from an injected
  clock.
- **Attachments** are files in the App Group container
  (`Attachments/<todo>/<attachment>/…` plus `attachments.json`). No schema
  change was needed for them. See `AttachmentStore`.
- **Widgets** render the output of the pure `WidgetContentBuilder`. Tapping a
  widget opens the app through the `howy://` URL scheme (`DeepLink`). The
  checkbox runs `CompleteTodoIntent`.
- **Panels** are borderless, non-activating `FloatingPanel`s (Spotlight/Raycast
  style). Only one is open at a time, and the panel's content is swapped instead
  of opening a new window.
- **Global shortcuts** use the `KeyboardShortcuts` package (Carbon hotkeys, so
  no Accessibility permission). The names are defined in `Howy/Shortcuts.swift`.

## Build and run

Run `xcodegen` after you add, remove or rename files, or after you change
`project.yml`. Commit the regenerated `.xcodeproj`.

```sh
xcodegen generate                                   # regenerate Howy.xcodeproj
xcodebuild -project Howy.xcodeproj -scheme Howy -configuration Debug \
  -derivedDataPath build/debug build                # debug build
xcodebuild -project Howy.xcodeproj -scheme Howy -configuration Release \
  -derivedDataPath build/release build              # release build → build/release/Build/Products/Release/Howy.app
```

`build/` is git-ignored. The app icon is an Icon Composer file
(`Howy/AppIcon.icon`), and `icon.afdesign` is its Affinity source.

## Tests

- Framework: **Swift Testing** (`import Testing`, `@Suite`, `@Test`, `#expect`).
  Don't use XCTest.
- All automated tests live in `Packages/HowyCore/Tests/HowyCoreTests` and run
  with SwiftPM:

  ```sh
  cd Packages/HowyCore && swift test
  ```

- Test behaviour through the public interface: feed key sequences into a flow
  and check the resulting state, or call `TodoStore` on an in-memory container
  with a `FakeClock` and check what comes out. Don't assert on private helpers,
  view hierarchies or SwiftData internals.
- New behaviour goes into `HowyCore` with a test, written test-first when
  practical. The app and widget targets have no unit tests. Check their UI by
  hand: run the app and try the changed screens and keys.
- Before you call a change done, `swift test` must pass and the `Howy` scheme
  must build with **no new warnings**.

## Conventions

- All UI text is in English.
- Commits use gitmoji + a conventional type: `:sparkles: feat: …`,
  `:lipstick: ui: …`, `:bug: fix: …`, `:memo: docs: …`, `:bookmark: release: …`.
- Work on `feat/*` or `fix/*` branches. `main` is the release branch.
- Update `CHANGELOG.md` (Keep a Changelog format) under **Unreleased** for every
  user-visible change. Bump `MARKETING_VERSION` in `project.yml` when you
  release, then regenerate.
- When behaviour changes, update `README.md` where it describes that behaviour,
  and the doc comments of the flow involved.

## Gotchas

- Don't use Option-only or Option+Shift-only global shortcuts. They're broken on
  macOS 15+.
- Widget missing from the gallery: check Console for "Group containers
  identifiers should be prefixed", and check that the extension is sandboxed.
- `KeyboardShortcuts` saves defaults on first launch. If you change a default
  shortcut, you need a migration (see the old ⌃⌥⇧⌘H → ⌃⌥⇧⌘M browse migration).
- Panels close when they lose key focus, with a short grace period after
  opening. Keep that in mind when you add flows that activate other apps or
  windows.
